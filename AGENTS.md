# Continuidade do Jogo PIF

- Antes de trabalhar, leia `CONTINUIDADE.md` e confira o estado real do Git e do código. O documento resume decisões, não substitui a implementação.
- Ao concluir uma entrega que altere código, assets ou decisões confirmadas de design, atualize `CONTINUIDADE.md` no mesmo trabalho. Separe implementado, confirmado para o futuro e propostas ainda não aprovadas. Registre validações e pendências reais.
- Comunique-se em português claro. Preserve trabalho local e arquivos não rastreados; não apague rascunhos nem use reset destrutivo.
- Commit e push exigem solicitação ou autorização do usuário na sessão. Atualizar este documento não autoriza publicar alterações automaticamente.
- Ao receber "ABRA O JOGO", consulte a versão mais recente do GitHub, preserve alterações locais, integre com cuidado, compile e abra o executável recém-compilado. Quando o usuário pedir explicitamente uma versão local/estas alterações, use essa versão sem substituí-la pela remota.
- Use `out/review` como diretório de build para os testes locais, evitando abrir um executável antigo em `build`. Execute com o diretório de trabalho junto dos assets copiados.
- Não afirme que as conversas do aplicativo ou arquivos ignorados pelo Git foram sincronizados. Esta continuidade é um arquivo versionado; só chega a outro computador após push e clone/pull. O OneDrive é um mecanismo separado.
- Não registre credenciais, tokens ou segredos nestes documentos.
